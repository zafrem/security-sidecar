security-sidecar

Every new web route gets a decision: public or secured. The decision is recorded next to the code, and the agent keeps secure-coding rules in mind for everything else it writes.

View on GitHub Playbook

Advice, not a firewall. A sidecar records intent and blocks nothing in its default annotate mode. The rules are guidance for the agent; they never mean code is secure.

What it does

Public or secured

When a route file is added, it is classified. Clear cases are saved silently; unsure ones ask you, and the default is secured.

Implementation guidance

Framework-specific steps: session checks inside the handler, ownership, rate limits, CSRF, caching and indexing.

Admin page protection

An extra gate (SSO, MFA or a passphrase of 8+ characters), a network restriction, and no links, sitemap or robots.txt entries unless you approve.

Risky-code lint

Flags eval, shell execution and string-built SQL. Suppressions are listed for review.

Secure-coding rules

14 language-neutral rules with TypeScript, Python, Go and Java notes, reminded at every session start.

Any code assistant

The same rules are generated for AGENTS.md, Cursor and Gemini.

A sidecar

app/admin-k7Qx92mVbT4nLw/.route.json
{
  "route": "/admin-k7Qx92mVbT4nLw",
  "mode": "annotate",
  "gate": { "type": "passphrase", "minLength": 16 },
  "enforcement": { "via": ["ip-allowlist"] },
  "reason": { "source": "user" }
}

Abbreviated: the real file also holds per-method exposure, cache and indexing. Illustrative values.

Install

/plugin marketplace add zafrem/security-sidecar
/plugin install security-sidecar --marketplace zafrem/security-sidecar

Then check a project: /security-sidecar:check. The CLI is bundled and needs only Node 18+.

Does the reminder help?

A small informal test: one prompt (an Express DELETE /files/:name handler), five runs each way.

Flags missing authentication0 of 55 of 5

Plugin runs left a TODO for authentication rather than adding it. One task and ten runs: it shows an effect, not its size.

Good to know

  • Enforcement output is Nginx only. Next.js is the tested framework; Express and FastAPI are detected by file path.
  • Link and lint checks are line-based text matching, so expect misses and some false positives.
  • reason.source: user is a convention an agent could forge, so review sidecar changes in pull requests.
  • Turn the session reminder off with "guidelines": false.
